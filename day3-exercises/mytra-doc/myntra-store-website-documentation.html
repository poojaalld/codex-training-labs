Myntra-Style Store Website Documentation

This document explains the current website in module4/myntra-style-store and summarizes the improvement ideas listed in module4/top-up-ideas. It is designed for learners, reviewers, and mentors who need a quick but complete understanding of the project.

Frontend React 19 + Vite single-page storefront
Backend Express 5 API serving curated catalog data
Goal Make the website and next improvements easy to understand

Project Snapshot

The project is a compact full-stack demo inspired by Myntra's merchandising style. The frontend fetches product data from an Express backend and renders a polished landing page with a hero section, category cards, product spotlight cards, and an architecture summary block. The stack is intentionally small, which makes it ideal for training and codebase-understanding exercises.

What the Website Currently Does

Frontend behavior

  • Shows a sticky header with navigation links and CTA buttons.
  • Displays a hero section with runtime status and catalog banner text.
  • Builds a category panel from fetched product categories.
  • Renders a product grid using reusable product cards.
  • Shows loading and error states based on API availability.

Backend behavior

  • Exposes GET /api/products.
  • Stores sample data in memory.
  • Formats prices using Indian currency formatting.
  • Returns a banner message and curated product list.
  • Allows cross-origin requests with cors().

Architecture Overview

Frontend flow

  1. main.jsx mounts the React app.
  2. App.jsx owns layout, state, and fetch logic.
  3. useEffect calls http://localhost:5174/api/products.
  4. The app stores products, banner, and status.
  5. useMemo derives unique categories from the product list.
  6. The UI updates based on loading, success, or error state.

Backend flow

  1. index.js creates the Express server.
  2. cors() and express.json() middleware are applied.
  3. A hard-coded product array acts as the temporary catalog.
  4. The API adds priceFormatted to every product.
  5. The response returns banner and curated.

Data Flow

Express product data
  -> /api/products response
  -> React fetch in App.jsx
  -> setBanner / setProducts / setStatus
  -> category extraction with useMemo
  -> product cards and category panel render
The project demonstrates a clean separation between backend data preparation, frontend state handling, and CSS-driven presentation. That is why it works well as a teaching example.

Key Files and Responsibilities

  • frontend/src/main.jsx: React entry point and root mounting.
  • frontend/src/App.jsx: page layout, fetch logic, derived categories, and rendering.
  • frontend/src/App.css: component and section styling.
  • frontend/src/index.css: global variables, fonts, and base styles.
  • backend/index.js: Express setup, product data, and API response shaping.

Current Strengths

  • Simple and understandable full-stack architecture.
  • Good example of React + API integration for beginners.
  • Responsive layout already exists.
  • Reusable product card pattern is data-driven.
  • Server-side currency formatting keeps display logic consistent.

Current Gaps and Limitations

  • The catalog is hard-coded and not persisted in a file or database.
  • No cart, filters, authentication, or checkout flow exists yet.
  • Backend logging and tests are missing.
  • Error handling is minimal.

Improvement Ideas from Top-Up Notes

Feature ideas

Engineering ideas

  • Move data to JSON or mock DB

Recommended Priority Order

  3. Add a filterable product drawer.
  4. Add a mini cart with saved local state.
  5. Add a rotating localized banner.
  6. Add a mega menu with accessibility states.

Conclusion

The Myntra-style store is a strong learning project because the complete request-response cycle is easy to trace from frontend UI to backend API. The current implementation already looks polished, but the improvement notes give a clear path toward a more realistic ecommerce experience. This makes the project ideal for both code understanding and guided enhancement work.
